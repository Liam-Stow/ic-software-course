Task: build a climber subsystem

Your mission

Build a climber from scratch — a motor-driven elevator that raises and lowers a hook, using position control just like the turret.

Almost every FRC game has a climbing challenge: the robot must lift itself onto a bar, rope, or hook at the end of the match. A common design is an elevator — a hook on a rack-and-pinion that a single motor drives up to latch the bar, then back down to pull the robot off the ground.

How a rack-and-pinion elevator works

A pinion gear on the motor meshes with a straight toothed rack. Spinning the pinion one way pushes the rack (and its hook) up; spinning it the other way pulls it down. So one motor, turning to a target position, controls the whole climb — exactly the position-control problem you solved for the turret.

The brief

Make a SubClimber subsystem that:

  • Has one motor on the pinion gear (a new CAN ID).
  • Uses PID position control to drive to a height — reuse what you did for the turret.
  • Has commands to raise and lower the hook (drive to two positions).
  • Is a Singleton, and is bound to buttons in RobotContainer.
  • Is simulated — but with an ElevatorSim instead of a FlywheelSim or DCMotorSim.

Think first: what electronic components does it have? What functions should it perform? Then build and test in the simulator.

Where to look if you're stuck

The climber is the turret with a different name and an ElevatorSim in place of the DCMotorSim. Revisit Lessons 20–23: parameterized commands, gear ratios/conversion factors, position simulation, and tolerances. The WPILib physics-sim docs ↗ describe ElevatorSim in detail.

This one is bigger than the feeder — give it a real go before peeking. Designing the subsystem yourself is the whole point.

SubClimber.h

#pragma once #include <frc2/command/SubsystemBase.h> #include <frc2/command/Commands.h> #include <frc/simulation/ElevatorSim.h> #include <frc/system/plant/DCMotor.h> #include <frc/system/plant/LinearSystemId.h> #include "utilities/ICSparkFlex.h" #include "Constants.h" class SubClimber : public frc2::SubsystemBase { public: SubClimber(); static SubClimber& GetInstance() { static SubClimber inst; return inst; } void Periodic() override; void SimulationPeriodic() override; frc2::CommandPtr Raise(); frc2::CommandPtr Lower(); bool AtTarget(); private: ICSparkFlex _climberMotor{canid::CLIMBER_MOTOR, 60_A}; // Physical characteristics for the simulation static constexpr double GEARING = 20; static constexpr units::kilogram_t CARRIAGE_MASS = 5_kg; static constexpr units::meter_t DRUM_RADIUS = 0.02_m; static constexpr units::meter_t MIN_HEIGHT = 0_m; static constexpr units::meter_t MAX_HEIGHT = 1_m; static constexpr frc::DCMotor MOTOR_MODEL = frc::DCMotor::NeoVortex(1); frc::sim::ElevatorSim _climberSim{ MOTOR_MODEL, GEARING, CARRIAGE_MASS, DRUM_RADIUS, MIN_HEIGHT, MAX_HEIGHT, true, 0_m}; };

SubClimber.cpp

#include "subsystems/SubClimber.h" #include <frc/smartdashboard/SmartDashboard.h> SubClimber::SubClimber() { rev::spark::SparkBaseConfig config; config.encoder.PositionConversionFactor(1.0 / GEARING); config.encoder.VelocityConversionFactor(1.0 / GEARING / 60.0); config.closedLoop.P(0.1); config.closedLoop.D(0.1); _climberMotor.AdjustConfig(config); frc::SmartDashboard::PutData("Climber motor", &_climberMotor); } void SubClimber::Periodic() { frc::SmartDashboard::PutBoolean("Climber AtTarget", AtTarget()); } void SubClimber::SimulationPeriodic() { _climberSim.SetInputVoltage(_climberMotor.CalcSimVoltage()); _climberSim.Update(20_ms); _climberMotor.IterateSim(_climberSim.GetVelocity()); } frc2::CommandPtr SubClimber::Raise() { return Run([this] { _climberMotor.SetPositionTarget(50_deg); }); } frc2::CommandPtr SubClimber::Lower() { return Run([this] { _climberMotor.SetPositionTarget(0_deg); }); } bool SubClimber::AtTarget() { return _climberMotor.OnPosTarget(1_deg); }

RobotContainer.cpp — bind raise/lower

#include "subsystems/SubClimber.h" void RobotContainer::ConfigureBindings() { _controller.POVUp().OnTrue(SubClimber::GetInstance().Raise()); _controller.POVDown().OnTrue(SubClimber::GetInstance().Lower()); }

Simulate, plot the climber height, and press the bindings — the carriage should drive to each target and hold. If it does, you've designed and simulated a brand-new mechanism on your own. That's the whole skill.

? Which simulation class fits a rack-and-pinion climber best?
An elevator lifts a mass against gravity, which is exactly what ElevatorSim models. FlywheelSim only tracks a spinning wheel's speed, and DCMotorSim is for a generic rotating shaft.
? Why is the climber such good practice right after the turret?
The climber is the turret's twin: one motor, PID position control, a conversion factor, and a physics sim. Building it cements everything from Module 5.
