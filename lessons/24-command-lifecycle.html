The command lifecycle

By the end

You'll understand the three stages every command goes through — Initialize, Execute and End — which is the key to building more complex actions.

Commands are robot actions that run over time. So far we've treated them as black boxes, but to automate the robot we need to understand what's happening inside. Every command has a start, a middle, and an end.

The three stages

More formally, those stages are called Initialize, Execute, and End:

  1. Initialize runs once, the moment the command starts.
  2. Execute runs in a loop, over and over (every 20 ms), for as long as the command is active.
  3. End runs once, when the command stops — whether it finished on its own or was interrupted.
You've already used these

Remember StartEnd back in the shooter? The name says it all: the first block was the start (Initialize) and the second was the end (End). And Run from the turret? That block was the Execute stage — the bit that repeats. The command factories are just convenient shortcuts for filling in these three stages.

Factories & decorators

WPILib provides a big toolbox of factories (which build common kinds of commands) and decorators (which change how a command behaves). Knowing what's in that toolbox lets you build complex actions simply. We've met StartEnd, Run, Wait, AlongWith and AndThen. Next we'll add Parallel, Sequence and WaitUntil.

? Which stage runs over and over in a loop while the command is active?
Execute is the repeating middle stage — it runs every 20 ms for as long as the command keeps running. Initialize and End each run exactly once.
? When does the End stage run?
End runs a single time when the command is done. It's where StartEnd put its cleanup block — like setting the motor back to 0.
