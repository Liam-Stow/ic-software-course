Constants & namespaces

By the end

Your CAN IDs will live in one tidy Constants.h file, referenced by name instead of by mystery numbers.

Right now the shooter's CAN ID is a bare 1 buried in SubShooter.h. As the robot grows we'll have many IDs, and hunting through files for them gets painful. Let's gather them in one place.

Create Constants.h

Inside src/main/include there is already a Constants.h file (the template made one). Open it and add a constant for the shooter motor:

#pragma once namespace canid { constexpr int SHOOTER_MOTOR = 1; }
Three new ideas, briefly
  • constexpr — like int but the value can never change while the program runs. Perfect for things that are fixed, like a CAN ID. (We use constexpr instead of the more common const mostly out of habit; both work here.)
  • ALL_CAPS — the naming convention for constants, so they stand out from normal variables.
  • namespace — a labelled group. Putting the ID inside a canid namespace lets us refer to it as canid::SHOOTER_MOTOR, which reads clearly and avoids name clashes.

Use the constant

Back in SubShooter.h, include Constants.h and swap the bare 1 for the named constant:

#include "Constants.h"
rev::spark::SparkFlex _shooterMotor{ canid::SHOOTER_MOTOR, rev::spark::SparkLowLevel::MotorType::kBrushless};
Why this is better

Now canid::SHOOTER_MOTOR tells a reader exactly what that number means, and if the ID ever changes you edit it in one place. As we add a feeder, a turret and a climber, all their IDs will live here together.
