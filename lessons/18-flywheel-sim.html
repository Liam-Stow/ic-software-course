Simulating the physics

By the end

Your simulated flywheel will actually spin up, because you'll model its physics with a FlywheelSim.

On a real robot, voltage goes into the motor and the wheel speeds up according to physics. In simulation there's no real wheel — so we build a little physics model that plays that role.

Add the simulation objects to the header

In SubShooter.h, add these includes and the simulation members. Also declare SimulationPeriodic():

#include <frc2/command/SubsystemBase.h> #include <frc2/command/Commands.h> #include <frc/simulation/FlywheelSim.h> #include <frc/system/plant/DCMotor.h> #include <frc/system/plant/LinearSystemId.h> #include "utilities/ICSparkFlex.h" #include "Constants.h"
void Periodic() override; void SimulationPeriodic() override; // runs every 20ms in simulation only bool AtTarget(); frc2::CommandPtr SpinFlywheel(); private: ICSparkFlex _shooterMotor{canid::SHOOTER_MOTOR, 60_A}; // Physical characteristics of the flywheel, for the simulation static constexpr double GEARING = 1.0; static constexpr units::kilogram_square_meter_t MOI = 0.01_kg_sq_m; static constexpr frc::DCMotor MOTOR_MODEL = frc::DCMotor::NeoVortex(1); frc::LinearSystem<1, 1, 1> _flywheelSystem = frc::LinearSystemId::FlywheelSystem(MOTOR_MODEL, MOI, GEARING); frc::sim::FlywheelSim _flywheelSim{_flywheelSystem, MOTOR_MODEL}; };
The new types, in plain English
  • GEARING is a double (a number with decimals). Our flywheel sits straight on the motor, so the ratio is 1.0.
  • MOI is a kilogram_square_meter_t — our first value with real units. It's the Moment of Inertia: how hard the wheel is to spin. Heavier/bigger wheels have a higher MOI.
  • MOTOR_MODEL is a frc::DCMotor: a maths model of a motor that knows how much torque it makes for a given voltage. We use a NEO Vortex, the motor usually paired with a Spark Flex.
  • _flywheelSystem is a frc::LinearSystem that ties the motor model, MOI and gearing together. The <1,1,1> means one state to control (speed), one input (voltage), one output (speed).
  • _flywheelSim is the FlywheelSim itself — the simulated wheel that runs the physics.

Run the simulation every loop

In SubShooter.cpp, define SimulationPeriodic(). This special function runs every 20 ms during simulation only (never on a real robot):

void SubShooter::SimulationPeriodic() { // Simulate the flywheel mechanism _flywheelSim.SetInputVoltage(_shooterMotor.CalcSimVoltage()); _flywheelSim.Update(20_ms); _shooterMotor.IterateSim(_flywheelSim.GetAngularVelocity()); }
The loop of information

Each step does three things:

  1. Ask the Spark how much voltage it's applying, and feed it into the physics sim.
  2. Advance the physics sim by 20 ms.
  3. Ask the sim how fast the wheel is now spinning, and hand that back to the Spark so its PIDF controller has a real measurement to work with.

Spark → voltage → physics → speed → back to Spark. Round and round, 50 times a second.

Test it

Simulate and hold the shoot button. Graph the shooter's target velocity and actual velocity together. You'll see the target jump to ~17 turns/sec (1000 RPM) — but the actual velocity stays flat at zero. That's the cliffhanger for the next lesson: we haven't tuned the gains yet.

? When does SimulationPeriodic() run?
It's the simulation-only counterpart to Periodic(). On a real robot the real wheel provides the feedback, so this function isn't used there.
? What does MOI (moment of inertia) describe?
Moment of inertia captures how resistant the wheel is to changes in spin. A heavier or larger-radius wheel has a higher MOI and takes more to accelerate.
