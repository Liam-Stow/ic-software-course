Checking when you're on target

By the end

Each subsystem will have an AtTarget() function that returns true or false — your first functions that hand back a result.

Soon we'll automate the whole shoot sequence. Before we can, the robot needs to be able to ask each subsystem: "are you on target yet?" — so it can wait for the turret to reach its angle and the shooter to reach its speed before feeding a ball.

Functions that return a result

Every function so far either returned a frc2::CommandPtr or nothing at all (void). AtTarget() is different — it needs to give back a yes/no answer. C++ stores yes/no values in a type called a bool (boolean): it's either true or false. To make a function return one, write bool where you'd normally write the return type.

Add AtTarget() to the shooter

Declare it in SubShooter.h alongside the other functions:

void Periodic() override; void SimulationPeriodic() override; bool AtTarget(); frc2::CommandPtr SpinFlywheel();

Now define it in SubShooter.cpp. We could write it the long way with an if/else:

bool SubShooter::AtTarget() { if (_shooterMotor.OnVelTarget(20_rpm)) { return true; } else { return false; } }
Why a tolerance of 20 RPM?

Notice we return true when we're within 20 RPM of the target, not only when we're exactly on it. Hitting an exact speed is almost impossible — the wheel might miss by 0.001 RPM forever. A tolerance of 20 RPM is plenty accurate for an FRC shooter and means AtTarget() can actually become true.

Because OnVelTarget() already returns true or false, the whole if/else is just passing that value straight through. We can simplify to one line:

bool SubShooter::AtTarget() { return _shooterMotor.OnVelTarget(20_rpm); }

Add AtTarget() to the turret

Same idea, but the turret cares about angle, so it uses OnPosTarget with a tolerance of 1 degree. Declare bool AtTarget(); in SubTurret.h, then:

bool SubTurret::AtTarget() { return _turretMotor.OnPosTarget(1_deg); }

Send the results to the dashboard

To check they work, publish each subsystem's answer in its Periodic():

void SubTurret::Periodic() { frc::SmartDashboard::PutBoolean("Turret AtTarget", AtTarget()); }
Test it
  • Simulate and watch the AtTarget booleans on the dashboard.
  • Command the turret to an angle — its boolean flips to true once it settles within 1°.
  • Hold the shoot button — the shooter's boolean flips to true once it's within 20 RPM.
? Why return true within a tolerance instead of only at the exact target?
Real mechanisms always miss the exact value by a tiny amount. A sensible tolerance (20 RPM, 1°) lets the check become true while staying accurate enough.
