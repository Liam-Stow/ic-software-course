Public, private & the Singleton

By the end

Your SubShooter will have a GetInstance() function, making it easy to reach from anywhere else in the program. The shooter subsystem will be complete!

We have one piece of housekeeping left before the shooter is done. Right now nothing outside SubShooter knows how to find it. Let's fix that.

Add GetInstance()

Jump back to SubShooter.h with Alt + O and add this function near the top of the public: section:

public: static SubShooter& GetInstance() { static SubShooter inst; return inst; } SubShooter();
This makes the subsystem a "Singleton"

A Singleton is a pattern that guarantees there's only ever one of something, and gives everyone a single shared way to get to it. There's only one physical shooter on the robot, so there should only be one SubShooter in code.

The full theory is a deep topic — for our purposes, SubShooter::GetInstance() simply hands back the one and only shooter, from anywhere in the program. You'll use exactly that in the next lesson to bind it to a button.

The shooter subsystem is complete 🎉

It contains a Spark Flex motor controller and can spin and stop. Next we'll let a human driver operate it.

? Why does a subsystem like SubShooter make a good Singleton?
There's a single physical shooter, so a single shared SubShooter object matches reality. GetInstance() gives every part of the program the same one to talk to.
? How will other code get hold of the shooter subsystem?
Calling SubShooter::GetInstance() returns the single shared instance. Making your own with new would create a second shooter, which we don't want.
