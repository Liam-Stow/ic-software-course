Binding commands to buttons

By the end

Pressing the A button on an Xbox controller will run your SpinFlywheel command.

RobotContainer connects triggers to commands

For a driver to use a subsystem, we hook its commands up to controller buttons. This happens in RobotContainer, the part of the code that connects Triggers (like the A button) to Commands (like SpinFlywheel).

Make a controller object

Open RobotContainer.h. Add the include up top and create a controller object down the bottom:

#pragma once #include <frc2/command/button/CommandXboxController.h> #include <frc2/command/CommandPtr.h>
private: frc2::CommandXboxController _controller{0};
Why the input 0?

The 0 means "the first controller plugged into the computer". Importantly, the count starts at 0, not 1, something you'll see all over computer code. You can have up to six controllers (IDs 0 to 5).

Include the subsystem in the body

Jump to RobotContainer.cpp and include your shooter near the top:

#include "subsystems/SubShooter.h"
Quotes " " vs chevrons < >

We wrap our own files in "quotes" and 3rd-party files in <chevrons>. Both work, but they start searching in different places. Quotes search our project's local files first which is minutely more efficient. More importantly though, it signals to any reader which files are ours and which come from outside.

Bind the command

Inside the existing ConfigureBindings() function, link SpinFlywheel to the A button:

void RobotContainer::ConfigureBindings() { _controller.A().WhileTrue(SubShooter::GetInstance().SpinFlywheel()); }
What WhileTrue means

This says: while the A button is held true (pressed), run SpinFlywheel. When A is first pressed, the command starts (setting the motor to 0.8 power). When A is released, the command is cancelled and ends (setting the motor to 0 power).

? Why is "subsystems/SubShooter.h" in quotes, not chevrons?
Quotes are the convention for our own project files. Chevrons are for libraries provided from outside. It makes the origin of each file obvious at a glance.
