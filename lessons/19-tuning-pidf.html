Tuning PIDF gains

By the end

Your flywheel's actual speed will match its target, and you'll have saved the gains you found into the code.

In the last lesson the target velocity jumped to 1000 RPM but the actual velocity didn't budge. That's because all the PIDF gains are still zero. Let's fix that by tuning live in the simulator, then lock the values into the code.

Tune live in NetworkTables

Because we sent the whole ICSparkFlex to the dashboard with PutData, its gains appear as editable fields in NetworkTables. Simulate, hold the shoot button, and graph target vs actual velocity. Then follow the recipe from Lesson 15:

  1. Set every gain to zero.
  2. Double the feedforward V until the actual velocity reaches the target speed.
  3. Raise P until it gets there quickly, without overshooting or oscillating.
  4. Leave I and D at zero — a well-made flywheel rarely needs them.
Reading the graph

Too little V/P: actual creeps up slowly or never reaches target. Too much P: actual overshoots and wobbles (oscillates) around the target. You're aiming for a quick rise that settles cleanly on the target line.

Save the gains in code

Live values in NetworkTables are lost when you close the sim. To keep them, save them in the constructor. PID gains go into a config sent to the Spark (so the controller runs onboard the motor controller, reducing sensing delays); feedforward is set with a direct function call:

SubShooter::SubShooter() { frc::SmartDashboard::PutData("Shooter motor", &_shooterMotor); rev::spark::SparkBaseConfig config; config.closedLoop.P(0.3); _shooterMotor.AdjustConfig(config); _shooterMotor.SetFeedforwardVelocity(0.11_V / 1_tps); }
What these numbers mean

Here we set P = 0.3 and V = 0.11. All the other gains (feedback I and D; feedforward S, G, A) stay at their default of zero. The feedforward is written 0.11_V / 1_tps — "0.11 volts per turn-per-second" — units that make the relationship between voltage and speed explicit.

Success looks like
  • Simulate again — the gains start already populated.
  • Hold the shoot button: actual velocity rises quickly and sits on the target.
  • The shooter now holds 1000 RPM regardless of simulated load. 🎉
? Why do we save the gains in the constructor instead of just tuning in NetworkTables?
Tuning live is how you find good gains, but those edits don't persist. Writing them into the constructor bakes them into the program for good.
? Following the recipe, which gain do you raise first?
Feedforward V does most of the work, so raise it first to get near the target, then add P to close the gap quickly. I and D usually stay at zero for a flywheel.
