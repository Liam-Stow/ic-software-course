Task: add a feeder subsystem

Module 2 ~25 min
🎯

Your mission

Build a feeder subsystem entirely on your own, the same way we built the shooter. No new concepts — this is practice.

A shooter needs something to push balls into the spinning flywheel. That's the feeder: a small wheel above the projectiles that rotates to push them up into the flywheel, firing them out.

The brief

Make a new subsystem for the feeder. It should:

  • Be called SubFeeder, in the subsystems folders.
  • Have a Spark Flex motor controller (give it a new CAN ID).
  • Have a command — call it Feed() — that runs the motor while held.
  • Be a Singleton (add GetInstance()).
  • Be bound to a different button (try the B button) in RobotContainer.

Test it in the simulator when it's ready.

Where to look if you're stuck

Everything you need is in Lessons 4–10. The feeder is built exactly like the shooter — just swap the names. Add a FEEDER_MOTOR constant to Constants.h alongside the shooter one.

Genuinely try it before peeking. Getting stuck and working through it is where the learning happens.

Show the solution — try it yourself first!

Constants.h

#pragma once namespace canid { constexpr int SHOOTER_MOTOR = 1; constexpr int FEEDER_MOTOR = 2; }

SubFeeder.h

#pragma once #include <frc2/command/SubsystemBase.h> #include <rev/SparkFlex.h> #include "Constants.h" class SubFeeder : public frc2::SubsystemBase { public: static SubFeeder& GetInstance() { static SubFeeder inst; return inst; } SubFeeder(); void Periodic() override; frc2::CommandPtr Feed(); private: rev::spark::SparkFlex _feederMotor{ canid::FEEDER_MOTOR, rev::spark::SparkLowLevel::MotorType::kBrushless}; };

SubFeeder.cpp

#include "subsystems/SubFeeder.h" SubFeeder::SubFeeder() = default; // This method will be called once per scheduler run void SubFeeder::Periodic() {} frc2::CommandPtr SubFeeder::Feed() { return StartEnd( [this] { _feederMotor.Set(1); // On Start }, [this] { _feederMotor.Set(0); // On End }); }

RobotContainer.cpp — bind to the B button

#include "subsystems/SubFeeder.h" void RobotContainer::ConfigureBindings() { _controller.A().WhileTrue(SubShooter::GetInstance().SpinFlywheel()); _controller.B().WhileTrue(SubFeeder::GetInstance().Feed()); }

Run the simulator and confirm the B button runs your feeder. If it does — great work, you just built a subsystem from scratch.

? Why must the feeder use a different CAN ID from the shooter?
Two devices sharing a CAN ID would be ambiguous — the code wouldn't know which one you mean. Each motor controller needs its own ID.
