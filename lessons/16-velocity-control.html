Velocity control with ICSparkFlex

~15 min
🎯

By the end

Your shooter will use an ICSparkFlex with a current limit, and SpinFlywheel will target an exact 1000 RPM instead of raw power.

Swap to ICSparkFlex

In SubShooter.h, change the include and the motor object. ICSparkFlex lives in the utilities you copied in Module 3:

#pragma once #include <frc2/command/SubsystemBase.h> #include <frc2/command/Commands.h> #include "utilities/ICSparkFlex.h" #include "Constants.h" class SubShooter : public frc2::SubsystemBase { public: static SubShooter& GetInstance() { static SubShooter inst; return inst; } SubShooter(); void Periodic() override; frc2::CommandPtr SpinFlywheel(); private: ICSparkFlex _shooterMotor{canid::SHOOTER_MOTOR, 60_A}; };
A different second input

The motor no longer takes a motor type — ICSparkFlex assumes a brushless motor. Instead its second input is a current limit: 60_A (60 amps). Setting current limits matters because:

  • Drawing lots of current for a long time heats the motor and can damage it.
  • Drawing lots of current starves other subsystems of power.

60 amps is a good starting point for the REV motors we use.

Target a speed, not a power

Now change SpinFlywheel() in SubShooter.cpp to target 1000 RPM (revolutions per minute):

frc2::CommandPtr SubShooter::SpinFlywheel() { return StartEnd( [this] { _shooterMotor.SetVelocityTarget(1000_rpm); // On Start }, [this] { _shooterMotor.Set(0); // On End }); }
SetVelocityTarget vs Set

Set(0.8) meant "80% power". SetVelocityTarget(1000_rpm) means "use the onboard PIDF controller to hold 1000 RPM, whatever power that takes". On end we still Set(0) to release the motor.

The _rpm unit again lets the compiler keep your units straight — no chance of confusing RPM with turns-per-second.

It won't actually spin up yet

If you simulate now, the target will read 1000 RPM but the actual speed stays at zero. That's expected — we haven't built the physics simulation (Lesson 18) or tuned the gains (Lesson 19) yet. One step at a time.

? Why set a current limit on a motor?
Sustained high current heats and can damage motors, and hogs the battery from everything else. A sensible limit (60 A for our REV motors) protects both.
