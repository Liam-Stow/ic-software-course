Functions & commands

By the end

Your shooter will have a SpinFlywheel() command that spins the motor at 80% power while it runs, and stops it when it ends.

Functions

A function is a block of code that can be called to run later. You can spot functions by the ( ) parentheses at the end of their names.

Declare the command in the header

Under public: in SubShooter.h, declare a function called SpinFlywheel(). Note, in some of these code blocks, we have removed the WPILib built-in comments (starting with // or /*). These comment lines in green exist to document and explain the code, they don't affect how it runs.

public: SubShooter(); void Periodic() override; frc2::CommandPtr SpinFlywheel();
Here, we make a function called SpinFlywheel() that creates an frc2::CommandPtr (pronounced “Command Pointer''), which is an action that our robot can perform. While in reality SpinFlywheel is a function that creates a command, when talking about these kinds of functions we often simplify things and just call them commands.
Public vs private

Notice the motor object from last lesson is private, but SpinFlywheel is public. The motor doesn't need to be touched from outside the subsystem, but the command does — other code (the button bindings) needs to reach it. So it has to be public.

Define it in the body

Next we need to tell the shooter how to spin its flywheel by giving our function a definition in the body file (ending in .cpp). Remember Alt+O can swap to the body file quickly. Swap over to the body file and add a blank defintion for our function:

frc2::CommandPtr SubShooter::SpinFlywheel() { }
Every line of code in between the { } braces of a function will run when we run (aka “call”) that function. Later on we'll call this function when a human driver presses a button on their controller. Fill the function with some code to control our Spark Flex:
frc2::CommandPtr SubShooter::SpinFlywheel() { return StartEnd( [this] { _shooterMotor.Set(0.8); // On Start }, [this] { _shooterMotor.Set(0); // On End }); }
These lines make a StartEnd command that will run one thing when it starts and another thing when it ends. On start we are telling the Spark Flex to spin the motor attached to it at 80% power, and on end we are telling it to spin at 0% power. Setting the motor back to 0% power is important as otherwise it would stay spinning even when the command stops. A command should almost always “clean itself up” in that way.
Always clean up

When a command ends, it should always leave the robot in a safe state. If a command starts a motor, it should stop it when it ends. Otherwise, the motor will keep running even after the command is done.

?How would you make a motor spin backwards?
_shooterMotor.set(0) makes the motor stay still, _shooterMotor.set(1) spins the motor at full power. In general, the more power you put to a motor, the faster it will spin. It's worth questioning yourself at this point, how do you think we could spin the motor backwards?
