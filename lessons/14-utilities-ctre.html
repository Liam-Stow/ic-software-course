Utilities & CTRE Phoenix

~12 min
🎯

By the end

Your project will contain IC's utilities helper code and the CTRE Phoenix vendor library, ready for the smarter motor control coming in Module 4.

IC has written helper code over the years that makes common jobs easier — most importantly a smarter motor-controller wrapper called ICSparkFlex. We'll borrow that helper code from the team project you just cloned.

Copy the utilities folders

From the IC project you cloned in the last lesson, copy the utilities folder from both:

  • src/main/cpp/utilities → into your project's src/main/cpp, and
  • src/main/include/utilities → into your project's src/main/include.

You should now see a utilities folder in your project's file explorer in VS Code.

Install CTRE Phoenix

Why another library?

Some of the utilities depend on a second vendor library: CTRE Phoenix, from Cross The Road Electronics. It mainly lets us use their TalonFX motor controllers. Even though our shooter uses a Rev Spark, the utilities reference Phoenix, so we need it installed for the project to build.

  1. Open the WPILib Vendor Dependencies sidebar.
  2. Install CTRE-Phoenix (v6) from the available list.
Check it builds

Build your code (Ctrl + Shift + P → WPILib: Build Robot Code). You want BUILD SUCCESSFUL again. If the build can't find utilities/ICSparkFlex.h or Phoenix types, re-check the two copy steps and that CTRE-Phoenix (v6) is installed.

Meet ICSparkFlex

From here on we'll swap our plain rev::spark::SparkFlex for IC's ICSparkFlex. It wraps the Rev Spark with extra powers: built-in PIDF velocity/position control, easy current limits, simulation helpers, and automatic dashboard reporting. That's exactly what Module 4 needs.

? Why do we install CTRE Phoenix even though our shooter uses a Rev Spark?
The utilities you copied reference Phoenix types, so the library must be present for the code to compile — even if you're not directly using a TalonFX yet.
