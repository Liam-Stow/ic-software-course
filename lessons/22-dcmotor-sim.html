Simulating position

By the end

Your simulated turret will actually rotate to an angle and hold there, because you'll model its physics with a DCMotorSim.

The flywheel used a FlywheelSim, which only tracks speed. A turret cares about where it's pointing, not just how fast it's turning — so we need a sim that tracks position too. That's the DCMotorSim.

Add the simulation objects to the header

In SubTurret.h, add these includes and simulation members, and declare SimulationPeriodic():

#include <frc2/command/SubsystemBase.h> #include <frc2/command/Commands.h> #include <frc/simulation/DCMotorSim.h> #include <frc/system/plant/DCMotor.h> #include <frc/system/plant/LinearSystemId.h> #include "utilities/ICSparkFlex.h" #include "Constants.h"
void Periodic() override; void SimulationPeriodic() override; frc2::CommandPtr TurnTo(units::degree_t angle); private: ICSparkFlex _turretMotor{canid::TURRET_MOTOR, 60_A}; // Constants static constexpr double GEARING = 20; static constexpr units::kilogram_square_meter_t MOI = 0.001_kg_sq_m; static constexpr frc::DCMotor MOTOR_MODEL = frc::DCMotor::NeoVortex(1); frc::LinearSystem<2, 1, 2> _turretSystem = frc::LinearSystemId::DCMotorSystem(MOTOR_MODEL, MOI, GEARING); frc::sim::DCMotorSim _turretSim{_turretSystem, MOTOR_MODEL}; };
<2, 1, 2> — why not <1, 1, 1>?

The flywheel system was <1, 1, 1>: one state (speed), one input (voltage), one output (speed). A turret tracks two states — its position and its velocity — so it's <2, 1, 2>: two states, one input (voltage), two outputs (position and velocity). That's the whole difference between simulating a spinning wheel and an aiming mechanism.

Run the simulation every loop

In SubTurret.cpp, define SimulationPeriodic(). It's the same three-step loop as the flywheel:

void SubTurret::SimulationPeriodic() { _turretSim.SetInputVoltage(_turretMotor.CalcSimVoltage()); _turretSim.Update(20_ms); _turretMotor.IterateSim(_turretSim.GetAngularVelocity()); }
Same loop, richer sim

The code looks identical to the flywheel's SimulationPeriodic() — voltage in, advance 20 ms, speed back out. The difference is inside _turretSim: because it's a DCMotorSim it also keeps track of the accumulated angle, which is exactly what position control needs to know.

Test it
  • Bind TurnTo(90_deg) to a button in RobotContainer (we'll wire it properly soon).
  • Simulate and graph the turret's target position and actual position.
  • Press the button: the actual angle should rise and settle on 90°. The gear ratio from last lesson means it lands on real turret degrees, not motor turns.
