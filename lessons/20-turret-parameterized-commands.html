A turret & commands with inputs

Module 5 ~18 min
🎯

By the end

You'll have a SubTurret subsystem with a TurnTo(angle) command — your first command that takes an input.

A shooter is better if you can aim it without turning the whole robot. So we'll add a turret: the shooter sits on a big toothed gear, and a motor rotates it to any angle. This is position control (an exact angle), where the flywheel was velocity control (an exact speed).

Create the turret subsystem

Make a new Subsystem called SubTurret (same steps as the shooter). Add a turret CAN ID to Constants.h, then set up its header with an ICSparkFlex:

namespace canid { constexpr int SHOOTER_MOTOR = 1; constexpr int FEEDER_MOTOR = 2; constexpr int TURRET_MOTOR = 3; }
#pragma once #include <frc2/command/SubsystemBase.h> #include <frc2/command/Commands.h> #include "utilities/ICSparkFlex.h" #include "Constants.h" class SubTurret : public frc2::SubsystemBase { public: SubTurret(); static SubTurret& GetInstance() { static SubTurret inst; return inst; } void Periodic() override; // Commands frc2::CommandPtr TurnTo(units::degree_t angle); // Rotate turret to angle. 0_deg = forward. private: ICSparkFlex _turretMotor{canid::TURRET_MOTOR, 60_A}; };
Commands with parameters

Every command so far did the exact same thing each time. TurnTo is different: it takes an input — the target angle. You give a function an input by writing the input's type and name inside the parentheses. Here that's units::degree_t angle: an angle, called angle. Now the one command can aim anywhere.

Define TurnTo in the body

We'll use a Run command (it runs its block repeatedly while active — ideal for continuously commanding a position):

frc2::CommandPtr SubTurret::TurnTo(units::degree_t angle) { return Run([this, angle] { _turretMotor.SetPositionTarget(angle); }); }
Notice [this, angle]

The square brackets are the lambda's "capture list" — the outside values the block is allowed to use. We capture this (so we can reach _turretMotor) and angle (so the block knows where to aim). The StartEnd blocks earlier only needed [this].

It's commanding motor turns, not degrees — yet

SetPositionTarget(angle) currently treats the angle as turns of the motor shaft, ignoring the gearbox between the motor and the turret. We'll fix that with a gear ratio in the next lesson.

? What makes TurnTo(angle) different from SpinFlywheel()?
By declaring units::degree_t angle in the parentheses, TurnTo can aim at any angle you pass in — one flexible command instead of many fixed ones.
