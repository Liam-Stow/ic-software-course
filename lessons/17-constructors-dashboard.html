Constructors & the dashboard

By the end

You'll use the subsystem's constructor to send the whole ICSparkFlex object to the dashboard once, so you can read and tune it live.

What's a constructor?

Every class has one special function with the same name as the class itself — the constructor. It runs once, when the object is first created. It's the perfect place for one-time setup. Right now SubShooter's constructor is "defaulted", meaning it does nothing:

SubShooter::SubShooter() = default;

Let the ICSparkFlex report itself

The ICSparkFlex can put all its own info on the dashboard for us. So we can delete the old PutNumber("shooter speed", ...) line from Periodic(), and instead send the whole object to the dashboard once, in the constructor:

#include "subsystems/SubShooter.h" #include <frc/smartdashboard/SmartDashboard.h> SubShooter::SubShooter() { frc::SmartDashboard::PutData("Shooter motor", &_shooterMotor); } // This method will be called once per scheduler run void SubShooter::Periodic() {}
Why the & in front of _shooterMotor?

The & is a C++ operator that gets the memory address of an object (also called a pointer or reference). PutData doesn't want the object itself — it wants to know where the object lives, so it can keep reading from it as values change. Hence we pass &_shooterMotor.

PutData vs PutNumber

PutNumber sends a single value. PutData sends a whole rich object — and because the ICSparkFlex knows how to describe itself, the dashboard will show its target velocity, actual velocity, and all its PIDF gains as editable fields. That's exactly what we need to tune it in Lesson 19.

? When does a constructor run?
A constructor runs a single time at creation — ideal for one-time setup like registering the motor with the dashboard, which we don't want to repeat 50 times a second.
? What does the & in &_shooterMotor do?
& yields the object's memory address. PutData needs to know where the object lives so it can keep reading live values from it.
